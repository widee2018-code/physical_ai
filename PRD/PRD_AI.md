입력 정보
제품명 (가정): OccuCool(오큐쿨) – 재실 인원 기반 냉난방 자동 제어 엣지 AI 컨트롤러
주요 입력 데이터: 천장 카메라 영상(기기 내 처리, 저장 안 함)에서 추출한 구역별 인원수, 실내 온도·습도 센서값, 에어컨 현재 상태(전원·설정온도·모드), (선택) 외기온도·운영 스케줄
주요 출력(행동): 에어컨 제어 명령(전원, 설정온도, 풍량, 모드), 습도 이상 시 제습 모드 전환, 이상 알림, 인원·온습도·에너지 로그 및 대시보드
1. 문제 정의 (Problem Statement)

현재 문제

사무실, 학교, 공공시설, 공장 등은 냉난방을 고정 스케줄이나 수동 조작으로 운영합니다.
사람이 없는 공간에서도 에어컨이 가동되어 에너지가 낭비되고, 회의나 점심 후처럼 인원이 급변할 때는 설정이 맞지 않아 더위·추위 민원과 반복 조작이 생깁니다.
(가정) 건물 전력 사용량 중 냉난방 비중은 약 40%이며, 근무시간 중 공실 시간 비율은 20~30%입니다.

기존 방식의 한계

고정 스케줄 타이머: 실제 재실과 무관하게 동작하며, 초과근무나 휴일 근무를 반영하지 못합니다.
PIR 모션센서: 움직임만 감지하므로 가만히 앉아 있으면 공실로 오판하고, 인원수는 알 수 없습니다.
CO₂ 센서: 인원 변화 후 수 분에서 십수 분 늦게 반응하고, 환기 상태에 따라 수치가 달라 인원 추정이 부정확합니다.
수동 조작: 담당자 의존도가 높고, 퇴근 후 끄는 것을 누락하기 쉽습니다.

핵심 가치

열부하의 원인인 "사람 수"를 직접 측정해 선제적으로 제어하므로, 에너지 절감과 쾌적도를 동시에 확보합니다.
영상은 기기 안에서만 처리하고 인원수 값만 외부로 전송합니다.

왜 AI가 필요한가

착석·정지 상태, 부분 가림, 다양한 조명 조건에서 사람 수를 세려면 규칙 기반 센서가 아닌 객체 검출 모델이 필요합니다.
인원수가 있어야 인체 발열(성인 1인 약 100~120W (가정))을 열부하 계산에 반영해 설정온도와 풍량을 정량적으로 조정할 수 있습니다.
v1은 규칙 기반 제어이며, 축적된 데이터로 v2에서 예측 제어를 검토합니다.
2. 사용자 시나리오 (User Scenario)

가정: 150㎡ 사무실 구역 1개, 컨트롤러 1대, 시스템 에어컨 1계통

설치: 설비 담당자가 천장(높이 2.4~3.5m (가정))에 컨트롤러를 설치하고 PoE 또는 DC로 전원을 연결합니다. 스마트폰 앱에서 BLE로 페어링한 뒤 에어컨 연동 방식(IR 또는 Modbus/BACnet 게이트웨이), 구역 면적, 기본 설정온도(냉방 26℃, 난방 22℃ (가정)), 퇴실 유예시간(10분 (가정))을 입력합니다. 소요 시간은 대당 약 30분 (가정)입니다.
데이터 수집: 카메라는 5fps (가정)로 영상을 처리하고 프레임은 메모리에서 즉시 폐기합니다. 온습도 센서는 10초 주기로 측정하고, 에어컨 상태는 1분 주기로 조회합니다.
AI 분석: 객체 검출 모델이 프레임별 인원수를 산출하고, 최근 5초 구간의 중앙값으로 깜빡임을 제거해 확정 인원수를 만듭니다.
판단 결과 생성: 제어 로직이 인원수, 실내온도, 설정온도, 외기온도로 목표 설정온도를 결정합니다. (가정) 냉방 기준은 다음과 같습니다.
0명: 유예시간 10분 후 절전(OFF 또는 설정온도 완화)
1~5명: 기본 설정온도 유지
6~10명: 설정온도 −1℃, 풍량 증가
11명 이상: 설정온도 −2℃, 풍량 최대
보호 장치: 설정 변경은 최소 5분 간격, ±0.5℃ 히스테리시스, 압축기 재기동 최소 3분 간격 (가정)
장치 제어: 판단 후 5초 이내에 에어컨으로 제어 명령을 전송하고, 명령 후 상태를 다시 읽어 적용을 확인합니다. 실패 시 3회 재시도하고, 계속 실패하면 알림을 보냅니다.
결과 확인 및 후속 행동:
담당자는 대시보드와 앱에서 구역별 인원, 실내온도, 가동 시간, 절감 전력량을 확인합니다.
제어 실패, 카메라 가림, 센서 이상, 오프라인 알림을 받으면 현장 점검을 합니다.
사용자가 수동으로 조작하면 2시간 (가정) 동안 수동 설정이 우선 적용된 뒤 자동 모드로 복귀합니다.
월간 리포트를 보고 유예시간과 기본 온도를 조정합니다.

예외 처리: 네트워크가 끊겨도 기기 내 로컬 제어는 계속됩니다. 카메라 이상 시 직전 설정을 유지하고 운영 스케줄로 전환합니다.

3. 성공 지표 (Success Metrics)
제품 가치
에너지 절감률: 도입 전 동일 조건 대비 15% 이상 (가정, 파일럿에서 10% 이상 검증). 측정은 구역별 전력량 전후 비교로 합니다.
쾌적도 유지율: 재실 중 실내온도가 설정온도 ±1.5℃ 이내인 시간 90% 이상. 측정은 온도센서 로그로 합니다.
수동 조작 감소: 도입 전 대비 50% 이상 감소. 측정은 조작 로그와 민원 접수 건수로 합니다.
AI 성능
인원 계수 정확도: 실제 인원 ±1명 이내 95% 이상, MAE 0.5명 이하 (0~15명, 주야간·부분 가림 포함). 측정은 수기 라벨링 테스트셋 1,000장 이상 (가정)으로 합니다.
추론 속도: 5fps 이상, 추론 지연 200ms 이하. 측정은 기기 로그로 합니다.
재실 중 절전 오작동: 구역당 월 1건 이하. 측정은 이벤트 로그와 현장 확인으로 합니다.
응답 시간
인원 변화 감지: 5초 이내. 측정은 이벤트 타임스탬프로 합니다.
제어 명령 전송: 감지 후 5초 이내 (실내온도 도달 시간과 별개). 측정은 명령 로그로 합니다.
퇴장 후 절전: 마지막 인원 퇴장 후 유예시간 10분 + 명령 전송 5초 이내. 측정은 이벤트 로그로 합니다.
신뢰성
제어 성공률: 99% 이상 (명령 후 상태 확인 기준). 측정은 상태 재조회 로그로 합니다.
온도 유지 안정성: 설정 변경 시간당 4회 이하, 압축기 최소 재기동 간격 위반 0건. 측정은 제어 로그로 합니다.
시스템 가동률: 월 99.5% 이상. 측정은 장치 헬스체크로 합니다.
오프라인 동작: 네트워크 단절 24시간 이상 로컬 제어 유지, 복구 후 로그 누락 0건. 측정은 단절 시험으로 합니다.
프라이버시
영상 외부 전송·저장: 0건. 측정은 네트워크 트래픽 감사로 합니다.
4. 기술 스택 (Technology Stack)
카메라
사용 기술: 2MP MIPI-CSI 광각(FOV 110~130°) RGB 카메라 모듈, 저조도용 IR 겸용 (가정)
선정 이유: 천장 장착 시 가림이 적고, 인원 계수에는 낮은 해상도로 충분합니다.
센서
사용 기술: 온습도 센서(Sensirion SHT4x 계열, I²C), 선택: CO₂(SCD4x), 선택: ToF/열화상(프라이버시 민감 현장용 대안)
선정 이유: 산업 표준 센서이고 정확도와 가격의 균형이 좋으며, 카메라 대체 옵션을 확보할 수 있습니다.
MCU / SoC
사용 기술: 메인은 Cortex-A 계열 + NPU SoC(예: NXP i.MX 8M Plus, NPU 2.3TOPS), 서브는 Cortex-M MCU(센서·릴레이·IR 송신·워치독). 소형 구역용 저가형은 Cortex-M55 + Ethos-U55급 MCU를 벤치마크 후 검토합니다.
선정 이유: 저전력 ARM 기반을 유지하면서 영상 추론 성능을 확보하고, 제어는 실시간 MCU가 안정적으로 담당합니다.
Edge AI
사용 기술: TensorFlow Lite 또는 ONNX Runtime + NPU 델리게이트, INT8 양자화
선정 이유: NPU 가속, 모델 이식성, 지연·전력 절감
AI 모델
사용 기술: 경량 객체 검출(YOLOv8n·YOLOX-nano급, 머리·상체 검출), 입력 320×320 (가정), 모델 크기 5~10MB (가정). 사전학습 후 천장 시점 자체 데이터로 미세조정합니다.
선정 이유: 5fps 이상 실시간 처리가 가능하고 저가 NPU에 탑재할 수 있습니다.
에어컨 제어 인터페이스
사용 기술: IR 송신(38kHz, 제조사별 코드 DB)은 가정용·스플릿용, RS-485 Modbus RTU·BACnet 게이트웨이는 상업용 시스템에어컨용, 제조사 Wi-Fi API는 P1
선정 이유: BLE만으로는 대부분의 에어컨을 제어할 수 없으므로 현장에서 쓰이는 인터페이스를 채택합니다.
로컬 통신
사용 기술: BLE 5.4 (설치·페어링·앱 연결)
선정 이유: 저전력, 스마트폰 호환성, 현장 설정 편의
서버 통신
사용 기술: Wi-Fi 또는 Ethernet(PoE) + MQTT over TLS
선정 이유: 경량 프로토콜이고 IoT 업계 표준이며 장치 인증서를 적용할 수 있습니다.
서버
사용 기술: AWS IoT Core + 컨테이너 기반 API 서버 (Azure IoT Hub 대체 가능)
선정 이유: 장치 관리, OTA, 규모 확장이 용이합니다.
데이터베이스
사용 기술: TimescaleDB(PostgreSQL 기반) 시계열 + PostgreSQL 메타데이터
선정 이유: 시계열 질의에 강하고 SQL 기반이라 운영이 쉽습니다. 영상은 저장하지 않습니다.
대시보드
사용 기술: React 웹 관리자 페이지 + Grafana(운영 모니터링)
선정 이유: 구역 설정·현황 조회와 장치 모니터링을 분리할 수 있습니다.
알림 시스템
사용 기술: FCM/APNs 푸시, 이메일, Slack 웹훅
선정 이유: 담당자가 쓰는 채널로 즉시 전달할 수 있습니다.
보안·OTA
사용 기술: 장치별 X.509 인증서, 보안 부트, 서명된 OTA
선정 이유: 장치 위변조를 막고 원격 업데이트의 보안을 확보합니다.
모바일 앱
사용 기술: Android/iOS (Flutter 또는 React Native), BLE 설정·알림 확인용
선정 이유: 기존 요구사항(Android/iOS)을 유지하고, 크로스플랫폼으로 개발 비용을 줄입니다.

6. ROI 분석 (Business Value)

분석 기준 (가정): 시설 운영사가 사무·공공시설 20개소(개소당 평균 6개 구역, 총 120대)에 초기 도입하는 프로젝트이며, 모든 수치는 가상의 값입니다.

초기 투자비 (CAPEX)
H/W 도입비: 컨트롤러 120대 × 450,000원 = 54,000,000원
에어컨 연동 모듈: IR·게이트웨이 120대 × 120,000원 = 14,400,000원
설치·시운전: 120대 × 150,000원 = 18,000,000원
AI 모델 초기 개발·현장 튜닝: 데이터 수집·라벨링·미세조정 = 60,000,000원
클라우드·대시보드 구축 및 라이선스: 서버 구축, 소프트웨어 라이선스 = 20,000,000원
초기 투자비 합계: 166,400,000원
월 절감액 (Gross Benefit)
냉난방 전기료 절감: 월 전기료 80,000,000원(20개소 × 4,000,000원) × 절감률 15% = 12,000,000원
인건비 절감: 개소당 월 6시간 × 30,000원 × 20개소 = 3,600,000원
설비 손실 감소: 압축기 가동·고장·유지보수 감소 = 1,200,000원
월 절감액 합계: 16,800,000원
월 운영비 (OPEX)
Edge 장치 전력비: 120대 × 8W × 720시간 ≈ 691kWh × 150원 = 약 104,000원
클라우드·DB: IoT 메시징, 시계열 DB, 대시보드 호스팅 = 600,000원
