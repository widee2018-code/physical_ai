## 1. GPIO (General Purpose Input/Output) — 디지털

### 1-1. 무엇인가

- 칩의 핀 하나를 **켜짐(1) / 꺼짐(0)** 두 상태로만 쓰는 가장 기본적인 인터페이스입니다.
- **출력 모드**: 핀 전압을 High(예: 3.3V) 또는 Low(0V)로 만들어 LED를 켜거나 트랜지스터를 스위칭합니다.
- **입력 모드**: 핀 전압이 임계값보다 높으면 1, 낮으면 0으로 읽습니다. 버튼, 디지털 출력 센서 상태를 읽습니다.
- **인터럽트**: 입력이 바뀌는 순간(상승/하강 엣지) CPU를 깨워 즉시 처리합니다. 계속 확인(폴링)할 필요가 없습니다.
- **PWM(펄스 폭 변조)**: 타이머로 GPIO를 빠르게 켰다 껐다 반복합니다. 주파수와 켜진 비율(듀티)로 LED 밝기 조절이나 IR 캐리어(38kHz)를 만듭니다.
- **입력 캡처**: 신호가 바뀐 시각을 타이머로 정밀하게 기록합니다. IR 리모컨 펄스 길이를 해독할 때 씁니다.

```
 디지털 신호        3.3V ┐   ┌───┐       ┌──── High = 1
                         │   │   │       │
                     0V  └───┘   └───────┘     Low  = 0

 PWM (듀티 1/3)     ┌┐ ┌┐ ┌┐ ┌┐       38kHz 캐리어 → IR 리모컨 신호
                   ─┘└─┘└─┘└─┘└──
```

### 1-2. 전기적 특성과 주의점

| 항목 | 내용 |
|---|---|
| 전압 레벨 | MCU는 보통 3.3V, i.MX 8M Plus는 뱅크별 1.8V 또는 3.3V. **서로 다르면 레벨 시프터 필요** |
| 출력 전류 | 핀당 수 mA~20mA 수준. **LED 1개는 직접 가능, IR LED(100mA 이상)나 코일은 MOSFET으로 구동** |
| 풀업/풀다운 | 입력 핀이 떠 있으면(Floating) 값이 무작위로 바뀜 → 내부 또는 외부 풀업/풀다운 저항 필요 |
| 디바운스 | 버튼은 누를 때 수 ms 동안 접점이 튐 → 소프트웨어로 10~50ms 무시 |
| 보호 | 외부로 나가는 핀은 직렬 저항(100Ω 내외)과 ESD 보호 |

### 1-3. OccuCool에서 GPIO에 연결하는 부품

| 부품 | 방향 | 사용 기능 | 연결 방법 | 이유 |
|---|---|---|---|---|
| **IR 송신 LED** (940nm ×3~5) | 출력 | **PWM 38kHz, 듀티 1/3** | MCU PWM 핀 → N-MOSFET 게이트 → LED(5V) | 에어컨 리모컨 신호 재현. LED 전류(100mA~1A 펄스)가 커서 MOSFET 필수 |
| **IR 수신기** (TSOP38238) | 입력 | **입력 캡처 + 인터럽트** | 수신기 OUT → MCU 핀 (3.3V) | 리모컨 코드 학습, 사용자의 수동 조작 감지(수동 조작 2시간 우선 규칙) |
| 페어링/리셋 버튼 | 입력 | 인터럽트 + 디바운스 | 내부 풀업, 버튼 → GND | BLE 페어링 진입, 길게 누르면 공장 초기화 |
| RGB 상태 LED | 출력 | PWM (밝기·깜빡임) | 핀 → 저항(330Ω~1kΩ) → LED | 정상 / 오프라인 / 안전 모드 / 페어링 표시 |
| 카메라 동작 표시 LED | 출력 | – | 카메라 전원 레일에 하드웨어 연동 권장 | 소프트웨어로 끌 수 없게 해 프라이버시 신뢰 확보 |
| 부저 (선택) | 출력 | PWM (2~4kHz) | 핀 → 트랜지스터 → 부저 | 설치 확인음 |
| IR-Cut 필터 전환 | 출력 | 2핀 (H-브리지 방향) | 핀 → 모터 드라이버 → 필터 코일 | 주간 IR 차단 / 야간 IR 통과 |
| IR 조명 ON/OFF (선택) | 출력 | PWM (밝기) | 핀 → 정전류 드라이버 EN | 야간 저조도 대응 |
| RS-485 방향 제어 (DE/RE) | 출력 | – | 핀 → 트랜시버 DE·/RE | 송신할 때만 버스를 구동 (UART와 짝으로 사용) |
| SoC 리셋 (워치독) | 출력 | 오픈 드레인 | MCU 핀 → SoC POR_B | SoC 하트비트가 끊기면 MCU가 재시작 |
| 센서 인터럽트/준비 신호 | 입력 | 인터럽트 | 센서 INT/RDY → 핀 | 데이터 준비 시점만 읽어 효율 향상 (계량 IC IRQ 등) |
| 외기 온도 DS18B20 (선택) | 양방향 | **1-Wire** (GPIO 1개로 구현) | 핀 + 4.7kΩ 풀업 | 수십 m 배선 가능, 핀 하나로 여러 센서 연결 |

> **1-Wire**는 GPIO 핀 1개로 데이터와 타이밍을 주고받는 별도 프로토콜입니다. 하드웨어 전용 블록 없이 소프트웨어(정밀 타이밍)로 GPIO를 제어해 구현합니다.

## 2. ADC (Analog-to-Digital Converter) — 아날로그

### 2-1. 무엇인가

- 0V~기준전압(예: 3.3V) 사이의 **연속적인 전압 값을 숫자로 바꾸는** 회로입니다.
- **분해능(비트)**: 12-bit ADC는 0~3.3V를 4,096단계로 나눔 → 한 단계 약 0.8mV.
- **샘플링 속도**: 1초에 몇 번 측정하는지 (SPS). 60Hz 교류 전류 파형을 보려면 최소 수 kSPS 필요.
- GPIO가 "높다/낮다"만 아는 반면 ADC는 "얼마나 높은지"를 압니다.

```
 아날로그 신호    3.3V ─            ╭─╮
 (연속 전압)                    ╭──╯  ╰──╮        → ADC가 일정 간격으로 측정
                   0V ─  ──────╯          ╰───     → 1024, 2051, 3890 ... 숫자로 저장

 변환식: 전압 = (ADC 값 / 4095) × 3.3V        (12-bit 기준)
```

### 2-2. 전기적 특성과 주의점

| 항목 | 내용 |
|---|---|
| 입력 범위 | 0V~VREF(보통 3.3V). **범위를 넘거나 음전압이 들어가면 칩 손상** → 분압 저항·클램프 다이오드 |
| 기준전압 정확도 | VREF가 흔들리면 모든 측정값이 같이 흔들림 → 정밀 측정은 외부 기준전압 IC |
| 잡음 | 디지털 잡음이 섞이기 쉬움 → RC 저역통과 필터(예: 1kΩ + 100nF), 아날로그 GND 분리 |
| 입력 임피던스 | 센서 출력 저항이 크면 측정 오차 → 버퍼(OP-AMP) 또는 샘플링 시간 늘리기 |
| i.MX 8M Plus | **범용 ADC가 거의 없음** → 아날로그 측정은 MCU의 ADC가 담당 |

### 2-3. OccuCool에서 ADC에 연결하는 부품

| 부품 | 입력 신호 | 연결 방법 | 이유 |
|---|---|---|---|
| **CT 전류 센서** (간이형, SCT-013-030: 30A → 1V) | 60Hz 교류 전압 (±1.4V 피크) | CT 출력 → **1.65V 바이어스 회로**(분압 저항 2개 + 커패시터)로 0~3.3V 범위에 올림 → MCU ADC | 교류는 음전압이 있어 그대로 넣으면 안 됨. 운전 상태(정지/송풍/압축기) 분류용 (hardware_report 7장 옵션 C) |
| 전원 전압 감시 | 12V / 5V 레일 | 분압 저항(예: 12V → 100kΩ:22kΩ → 약 2.2V) → ADC | 어댑터·PoE 이상, 전압 저하 감지 → 안전 모드·알림 |
| 방열판 온도 (NTC 서미스터, 선택) | 저항 변화 → 전압 | NTC + 고정 저항 분압 → ADC | SoC 과열 시 프레임 샘플링을 낮추는 적응형 처리(check_list 9-4) |
| 조도 센서 (포토다이오드/CdS, 선택) | 빛 → 전압 | 분압 또는 트랜스임피던스 → ADC | IR 조명 ON/OFF, 저조도 판단 (파일럿 현장은 LED 상시 점등이라 생략 가능) |

> **CT를 ADC에 직접 연결하지 않는 경우**: 정확한 유효전력(W)과 적산(Wh)이 필요하면 전력 계량 IC(SPI, 4장)나 외장 Modbus 전력량계(UART, 5장)를 쓰고 ADC는 쓰지 않습니다. **권장 구성은 외장 Modbus 전력량계**입니다(220V를 기기 안으로 들이지 않음).

> **온습도를 ADC로 읽지 않는 이유**: 아날로그 출력 센서는 배선 잡음과 ADC 오차가 그대로 측정값에 섞입니다. SHT4x처럼 센서 안에서 디지털로 변환해 I²C로 보내는 방식이 더 정확하고 보정도 끝난 상태로 받습니다.

## 3. I²C (Inter-Integrated Circuit)

### 3-1. 무엇인가

- **2선(SDA 데이터, SCL 클럭)** 으로 여러 장치를 한 버스에 연결하는 동기식 직렬 통신입니다.
- 마스터(MCU/SoC)가 클럭을 만들고, 각 장치는 **7-bit 주소**로 구분합니다. 같은 선에 센서 여러 개를 매달 수 있어 핀을 아낍니다.
- **오픈 드레인** 방식이라 선을 Low로 당기기만 하고, High는 **풀업 저항**(보통 4.7kΩ)이 만듭니다.
- 속도: Standard 100kHz, Fast 400kHz, Fast-mode Plus 1MHz.

```
         3.3V ─┬────────┬─── 풀업 4.7kΩ ×2
               │        │
 MCU  SDA ─────┴──┬─────┴────┬──────────┬──────────┐
      SCL ────────┼──┬───────┼──┬───────┼──┬───────┼──┬──
                  │  │       │  │       │  │       │  │
               SHT4x(0x44)  SCD41(0x62)  RTC(0x52)  (추가 센서)

 통신 순서: [시작] → [주소 7bit + 읽기/쓰기] → [ACK] → [데이터] → [ACK] → [정지]
```

### 3-2. 전기적 특성과 주의점

| 항목 | 내용 |
|---|---|
| 배선 길이 | 기판 위나 **1m 이내** 권장. 길면 선 용량 때문에 신호가 무너짐 → 벽면 원격 센서는 I²C 대신 RS-485나 Wi-Fi |
| 풀업 저항 | 버스당 한 세트만. 브레이크아웃 보드마다 풀업이 있으면 병렬로 겹쳐 너무 강해짐 |
| 주소 충돌 | 같은 주소 장치 2개는 같은 버스에 불가 → 주소 변경 핀, 다른 버스, I²C 멀티플렉서(TCA9548A) |
| 전압 레벨 | 1.8V 장치와 3.3V 장치를 섞으면 레벨 변환기(PCA9306 등) 필요 |
| 버스 멈춤 | 장치가 SDA를 Low로 붙잡고 멈추는 경우 → SCL 9회 토글로 복구하는 코드 필요 |

### 3-3. OccuCool에서 I²C에 연결하는 부품

| 부품 | 주소 | 속도 | 연결 대상 | 이유 |
|---|---|---|---|---|
| **SHT4x 온습도 센서** | 0x44 | 400kHz~1MHz | MCU | 핵심 센서. 센서 안에서 보정·디지털 변환 완료, 10초 주기 측정 |
| SCD41 CO₂ 센서 (선택) | 0x62 | 100kHz | MCU | 환기 품질 알림. **I²C 최대 100kHz**라 같은 버스의 속도를 100kHz로 맞추거나 버스를 분리 |
| RTC (RV-3028) | 0x52 | 400kHz | MCU | 오프라인 시 로그 시각 유지. MCU가 시계를 쥐고 있어야 SoC 재부팅 중에도 시각 기록 가능 |
| 보안 소자 SE050 | 0x48 | 400kHz~ | **SoC** | X.509 개인키 보관, TLS 인증을 SoC 리눅스가 수행하므로 SoC 쪽 버스 |

| PMIC PCA9450C | 0x25 | 400kHz | **SoC** | 코어 전압 조절(DVFS). SoM 내부 연결 |
| 열화상 MLX90640 (선택) | 0x33 | 최대 1MHz | MCU 또는 SoC | 카메라 대체 현장용. 32×24 프레임이라 데이터가 많아 1MHz 권장 |
| ToF VL53L5CX (선택) | 0x29 | 최대 1MHz | MCU 또는 SoC | 카메라 대체 현장용. 첫 부팅 시 펌웨어 약 80KB 업로드 필요 |

**버스 구성 권장안**

| 버스 | 마스터 | 장치 | 속도 |
|---|---|---|---|
| I²C-1 | MCU | SHT4x, RTC | 400kHz |
| I²C-2 | MCU | SCD41 (선택) | 100kHz |
| I²C-3 | SoC | SE050, (SoM 내부) PMIC | 400kHz |
| I²C-4 | SoC | 카메라 SCCB | 400kHz |

> 주소 충돌은 없습니다: 0x25, 0x29, 0x33, 0x44, 0x48, 0x52, 0x62.

## 4. SPI (Serial Peripheral Interface)

### 4-1. 무엇인가

- **4선**으로 동작하는 고속 동기식 직렬 통신입니다.
  - **SCLK**: 마스터가 만드는 클럭
  - **MOSI** (Master Out Slave In): 마스터 → 장치 데이터
  - **MISO** (Master In Slave Out): 장치 → 마스터 데이터
  - **CS** (Chip Select): 통신할 장치를 고르는 선 (Low일 때 선택)
- 보내기와 받기가 **동시에(전이중)** 일어나고, 주소가 없어 오버헤드가 적어 **I²C보다 10~50배 빠릅니다**.
- 장치가 늘어날 때마다 **CS 핀이 하나씩 더** 필요합니다.
- **모드 0~3**: 클럭 극성(CPOL)과 위상(CPHA) 조합. 장치 데이터시트의 모드에 맞춰야 합니다.

```
 MCU (마스터)                  계량 IC          외장 플래시
   SCLK ──────────────────┬───────────┬──────────────
   MOSI ──────────────────┼──┬────────┼──┬───────────
   MISO ──────────────────┼──┼──┬─────┼──┼──┬────────
   CS0  ──────────────────┘  │  │     │  │  │   (계량 IC 선택)
   CS1  ─────────────────────┴──┴─────┘  │  │   (플래시 선택)
```

### 4-2. I²C와 SPI 비교

| 항목 | I²C | SPI |
|---|---|---|
| 선 수 | 2선 (장치가 늘어도 그대로) | 3선 + 장치당 CS 1선 |
| 속도 | 100kHz~1MHz | 1~50MHz |
| 장치 구분 | 주소 | CS 핀 |
| 통신 방향 | 반이중 | 전이중 |
| 확인 응답 | ACK 있음 | 없음 (CRC는 장치가 제공하면 사용) |
| 적합한 용도 | 느리고 작은 데이터 (센서 값 몇 바이트) | 빠르거나 많은 데이터 (계량 파형, 메모리, 디스플레이) |

### 4-3. OccuCool에서 SPI에 연결하는 부품

| 부품 | 클럭 | 연결 대상 | 이유 |
|---|---|---|---|
| **전력 계량 IC** (ATM90E26, 옵션 B) | 최대 수 MHz, 모드 3 | MCU | CT 전류와 220V 전압 파형을 칩 안에서 계산해 유효전력·Wh를 레지스터로 제공. 레지스터를 자주 읽어 SPI가 유리 (UART 모드도 지원) |
| 외장 SPI NOR 플래시 (선택, 예: 8~16MB) | 최대 수십 MHz | MCU | SoC가 꺼져 있는 동안 MCU가 기록하는 온습도·제어 로그 버퍼 |
| (대안) SoC ↔ MCU 통신 | 1~10MHz | SoC(마스터) ↔ MCU(슬레이브) | UART보다 빠름. 다만 OccuCool의 데이터량(인원수, 명령)은 작아 **UART로 충분**하므로 기본안은 UART |
| (참고) 디스플레이 | 수십 MHz | – | v1에는 디스플레이 없음 |

> 카메라 영상은 SPI로 보내지 않습니다. 2MP × 5fps는 SPI 대역폭을 크게 넘어 CSI를 씁니다.

## 5. UART (Universal Asynchronous Receiver/Transmitter)

### 5-1. 무엇인가

- **TX(송신)와 RX(수신) 2선**으로 1:1 통신하는 **비동기** 직렬 통신입니다. 클럭 선이 없습니다.
- 양쪽이 미리 같은 **보레이트(bps)** 를 정해 두고, 시작 비트로 박자를 맞춥니다.
- 프레임 형식 예: **8N1** = 데이터 8비트, 패리티 없음(N), 정지 비트 1. 8E1은 짝수(Even) 패리티.
- **연결은 교차**: A의 TX → B의 RX, A의 RX → B의 TX, GND 공통.
- **RTS/CTS 흐름 제어**: 받는 쪽 버퍼가 꽉 차면 송신을 멈추게 하는 선 2개 (블루투스 모듈은 필수).

```
  SoC            MCU             1바이트 프레임 (8N1, 0x55)
  TX  ─────────▶ RX
  RX  ◀───────── TX              ──┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌──
  GND ────────── GND               └─┘ └─┘ └─┘ └─┘ └─┘
                                 시작 D0 ... D7 정지
```

### 5-2. RS-485는 UART와 어떤 관계인가

- UART는 칩 사이 짧은 거리(수십 cm)용 **TTL 레벨(0/3.3V)** 신호입니다.
- **RS-485는 UART 신호를 차동(A/B 두 선의 전압 차)으로 바꿔** 최대 1,200m까지, 최대 32대 이상 장치에 보내는 **물리 계층**입니다.
- 그 위에서 **Modbus RTU**(주소 + 기능 코드 + 데이터 + CRC) 같은 프로토콜로 대화합니다.

```
 MCU UART TX ─▶ ┌──────────────┐  A ═══════════════╦═══════════╦══ (120Ω 종단)
 MCU UART RX ◀─ │ RS-485       │  B ═══════════════╬═══════════╬══
 MCU GPIO DE ─▶ │ 트랜시버     │                   ║           ║
                └──────────────┘            시스템 에어컨   Modbus 전력량계
                                            (주소 1)        (주소 2)
```

### 5-3. 주의점

| 항목 | 내용 |
|---|---|
| 보레이트 오차 | 양쪽 클럭 오차 합이 약 2%를 넘으면 글자가 깨짐 → 정확한 크리스털 사용 |
| 데이터 무결성 | UART 자체는 오류 검출이 약함(패리티 정도) → **CRC16 + 시퀀스 번호**를 패킷에 넣음 |
| 전압 레벨 | SoC(1.8V/3.3V)와 MCU(3.3V) 레벨 확인. **RS-232(±12V)를 직접 연결하면 칩 손상** |
| RS-485 반이중 | 한 번에 한 장치만 송신 → DE 핀을 정확히 송신 중에만 켜야 함 |

### 5-4. OccuCool에서 UART에 연결하는 부품

| 연결 | 보레이트 / 형식 | 물리 계층 | 이유 |
|---|---|---|---|
| **SoC ↔ 서브 MCU** | 115,200~921,600bps, 8N1, CRC16 패킷 | TTL UART (3.3V) | 인원수·재실 상태(SoC→MCU), 온습도·에어컨 상태(MCU→SoC), 1초 하트비트. 배선 2개로 단순하고 디버깅이 쉬움 |
| **RS-485 → 시스템 에어컨** | 9,600 / 19,200bps, 8N1 또는 8E1 | RS-485 (절연형 트랜시버) | Modbus RTU로 전원·설정온도·풍량·모드 쓰기, **상태 읽기(피드백)** |
| **RS-485 → Modbus 전력량계** (권장 에너지 측정) | 9,600bps | 같은 RS-485 버스 공용 | 유효전력·Wh 읽기, 운전 상태 교차 검증 (E1, A2) |
| RS-485 → 외기 온습도 트랜스미터 (선택) | 9,600bps | 같은 RS-485 버스 공용 | 장거리 유선, 결측 적음 |
| RS-485 → BACnet MS/TP 게이트웨이 | 9,600~76,800bps | RS-485 | 상업용 시스템 에어컨 그룹 제어 |
| **SoC ↔ 블루투스 (Wi-Fi/BLE 콤보 모듈)** | 최대 3Mbps, **RTS/CTS 필수** | TTL UART (1.8V) | BLE 설치·페어링. 표준 HCI 프로토콜 |
| 디버그 콘솔 (SoC, MCU 각각) | 115,200bps | TTL UART → USB 변환 케이블 | 부팅 로그, 현장 진단 |
| 전력 계량 IC (UART 모드, 대안) | 9,600bps | TTL UART | SPI 핀이 부족할 때 대안 |

**MCU UART 할당 예**: UART1 = SoC 연결, UART2 = RS-485, UART3 = 디버그 → MCU는 **UART 3개 이상** 필요

## 6. CSI / USB — 고속 인터페이스

### 6-1. MIPI CSI-2 (Camera Serial Interface)

**무엇인가**
- 이미지 센서와 프로세서를 잇는 **카메라 전용 고속 직렬 인터페이스**입니다. 스마트폰 카메라의 표준입니다.
- 물리 계층 **D-PHY**: 클럭 1쌍 + 데이터 **1·2·4 lane**(각 lane은 차동 2선). lane당 약 1~2.5Gbps.
- 영상 데이터만 CSI로 흐르고, 센서 설정(노출, 해상도)은 **별도 I²C(SCCB)** 로 합니다.
- 압축 없는 원본(RAW/YUV)을 그대로 보내 **지연이 매우 짧고**, SoC의 **ISP**가 바로 처리합니다.

```
 이미지 센서 (IMX462)                     i.MX 8M Plus
   CLK+/CLK− ════════════════════════════▶ CSI 수신기 → ISP → 메모리 → NPU
   D0+/D0−   ════════════════════════════▶   (프레임은 RAM에서만 처리 후 폐기)
   D1+/D1−   ════════════════════════════▶
   SDA/SCL   ────────── I²C 설정 ─────────  
   RESET/PWDN ─────────  GPIO  ──────────  
```

**주의점**
| 항목 | 내용 |
|---|---|
| 배선 길이 | FPC 케이블 **약 30cm 이내** 권장. 길면 신호 품질 저하 |
| 임피던스 | 차동 100Ω 정합, 쌍 내 길이 맞추기 (기판 설계 규칙) |
| 드라이버 | 센서마다 리눅스 드라이버·ISP 튜닝 파일이 필요 → **SoC 벤더가 지원하는 센서**를 고르는 것이 개발 기간을 크게 줄임 |

**대역폭 계산 (OccuCool)**
- 1920 × 1080 × 10bit(RAW10) × 5fps ≈ **104Mbps** → 2-lane CSI의 여유가 매우 큼. 30fps(약 620Mbps)도 가능

### 6-2. USB (Universal Serial Bus)

**무엇인가**
- PC 주변기기용 범용 고속 직렬 인터페이스입니다. **전원(VBUS 5V)과 데이터(D+/D− 차동)** 를 한 케이블로 보냅니다.
- 호스트(SoC)가 모든 통신을 주도하고, 허브로 여러 장치를 연결합니다.
- 속도: USB 2.0 Full-Speed 12Mbps / High-Speed 480Mbps, USB 3.0 5Gbps (추가 차동쌍 2개).
- **장치 클래스**로 드라이버 없이 동작: UVC(카메라), CDC-ACM(가상 시리얼), MSC(저장장치).

**CSI 카메라 vs USB 카메라**

| 항목 | MIPI CSI 카메라 | USB(UVC) 카메라 |
|---|---|---|
| 지연 | 매우 짧음 (ISP 직결) | 상대적으로 김 (보통 MJPEG 압축 → 해제 필요) |
| CPU 부하 | 낮음 (ISP가 처리) | 압축 해제에 CPU 사용 |
| 배선 길이 | 약 30cm | 최대 5m |
| 개발 편의 | 드라이버·튜닝 필요 | 꽂으면 바로 동작 |
| 노출·WB 고정 | ISP에서 세밀 제어 | 카메라 펌웨어 기능에 의존 |
| 적합 단계 | **양산 제품** | **개발·PoC** |

### 6-3. OccuCool에서 CSI/USB에 연결하는 부품

| 부품 | 인터페이스 | 단계 | 이유 |
|---|---|---|---|
| **2MP 광각 카메라 (IMX462, 110~130°)** | **MIPI CSI-2 2-lane** (+ I²C 설정) | 양산 | 저지연·저전력, ISP로 노출·WB 고정(전처리 V1), 영상이 RAM 밖으로 나가지 않는 구조 |

## 9. 인터페이스 선택 기준 정리

| 질문 | 답 | 선택 |
|---|---|---|
| 켜고 끄기만 하면 되나? | 예 | **GPIO** |
| 정해진 주파수의 펄스가 필요한가? (IR, 밝기) | 예 | **GPIO + PWM** |
| 센서가 전압 크기로 값을 내보내나? | 예 | **ADC** |
| 느린 디지털 센서 여러 개를 핀 적게 연결? | 예 | **I²C** |
| 데이터가 빠르거나 많고 거리가 짧은가? | 예 | **SPI** |
