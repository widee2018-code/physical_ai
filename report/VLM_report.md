# 비전·비전-언어 모델 6종 비교 보고서 (MediaPipe · OCR · SAM2 · SigLIP2 · YOLOE · DINO-X)

작성일: 2026-10-12
검토 자료: `mediapipe/`, `OCR/`, `SAM2/`, `sigLIP2/`, `YOLO_E/` 폴더의 예제 코드와 `outputs/` 결과 이미지, DINO-X 논문(arXiv 2411.14347)과 공식 API 저장소(`IDEA-Research/DINO-X-API`)
실행 장비: MacBook Air M4 (SigLIP2는 `mps` 사용)

> DINO-X는 이 프로젝트에서 직접 실행하지 않았습니다. 1-6절과 비교표의 DINO-X 항목은 **공개 자료 기준**이며, 시연 결과가 없습니다.
>
> 용어 정리: 이 6개 중 **텍스트와 이미지를 함께 다루는 모델은 SigLIP2, YOLOE(텍스트 프롬프트 모드), DINO-X** 입니다. 셋이 좁은 의미의 비전-언어 모델(VLM)에 해당합니다. MediaPipe, PaddleOCR, SAM2는 순수 비전 모델입니다. OCR은 이미지에서 글자를 읽지만, 글자의 뜻을 이해하지는 않습니다.

## 0. 요약

| 모델 | 한 줄 설명 | 입력 | 출력 | 크기 (시연 모델) |
|---|---|---|---|---|
| **MediaPipe** | 사람의 얼굴·손·몸 키포인트를 찾고 제스처를 분류 | 이미지 | 랜드마크 좌표, 제스처 라벨, 표정 계수, 사람 마스크 | 3.7~9.4MB (`.task`) |
| **PaddleOCR (PP-OCRv5)** | 이미지 속 글자의 위치를 찾고 읽음 | 이미지 | 텍스트 + 신뢰도 + 4점 폴리곤 | 자동 다운로드 (수십 MB) |
| **SAM 2.1** | 위치(점·박스)를 알려주면 그 물체의 정확한 윤곽을 잘라냄 | 이미지 + 점/박스 | 픽셀 단위 마스크 (클래스 없음) | 78MB (`sam2.1_t.pt`) |
| **SigLIP2** | 이미지와 문장을 같은 벡터 공간에 넣어 유사도를 계산 | 이미지 + 텍스트 | 임베딩 벡터, 코사인 유사도 | base-patch16-224 (약 375M 파라미터) |
| **YOLOE** | 텍스트·예시 박스·프롬프트 없이 원하는 물체를 탐지·분할 | 이미지 (+ 텍스트/박스) | 박스 + 클래스 + 마스크 | 31MB / 40MB(-pf) + 텍스트 인코더 254MB |
| **DINO-X** | 열린 어휘 탐지에 분할·키포인트·영역 설명까지 하나로 묶은 통합 모델 | 이미지 (+ 텍스트/박스) | 박스 + 클래스 + 마스크 + 키포인트 + 캡션 | 가중치 비공개, 클라우드 API로 사용 |

**핵심 차이 한 문장씩**

- **MediaPipe**는 "사람의 몸이 어떻게 생겼는가"(구조)를 봅니다.
- **OCR**은 "무엇이 쓰여 있는가"(글자)를 봅니다.
- **SAM2**는 "어디부터 어디까지가 한 물체인가"(경계)를 봅니다.
- **SigLIP2**는 "이 이미지가 이 문장과 얼마나 비슷한가"(의미)를 봅니다.
- **YOLOE**는 "무엇이 어디에 있는가"(클래스 + 위치)를 봅니다.
- **DINO-X**는 "무엇이 어디에 어떤 모양·자세로 있고, 어떻게 설명되는가"(위치 + 형태 + 설명)를 한 번에 봅니다.

## 1. 모델별 기능 설명

### 1-1. MediaPipe (Google)

**무엇을 하는가**: 사람 전용 모델 묶음입니다. 가벼운 `.task` 파일 하나로 CPU에서도 실시간으로 돌아갑니다. 시연한 4가지 태스크는 다음과 같습니다.

| 태스크 | 스크립트 | 출력 | 시연 결과 |
|---|---|---|---|
| Face Landmarker | `face_landmark_example.py` | 얼굴 **478개 3D 랜드마크**(메시, 눈·입술 윤곽, 홍채) + **52개 블렌드쉐이프**(눈 깜빡임, 미소 등 표정 계수) | `outputs/face_landmark.jpg`, 상위 5개 표정 계수 표시 |
| Hand Landmarker | `hand_landmark_example.py` | 손 **21개 키포인트** + 왼손/오른손 구분 | `outputs/hand_landmark.jpg`, 두 손 검출 |
| Gesture Recognizer | `gesture_recognition_example.py` | 손 랜드마크로 **7가지 제스처** 분류 (Closed_Fist, Open_Palm, Pointing_Up, Thumb_Down, Thumb_Up, Victory, ILoveYou) | `outputs/gesture_recognition.jpg`, 4장 이어 붙임 |
| Pose Landmarker | `pose_landmark_example.py` | 전신 **33개 키포인트** + visibility + **사람 분할 마스크** | `outputs/pose_landmark.jpg`, 사람 영역 초록 오버레이 |

**특징**

- 좌표는 0~1로 정규화된 값입니다. 이미지 크기가 달라도 같은 코드로 처리할 수 있습니다.
- 사람에 특화된 모델입니다. 사람 이외의 물체는 찾지 못합니다.
- 정면이나 측면 시점의 데이터로 학습되었습니다. 천장에서 내려다보는 시점에서는 정확도가 크게 떨어질 수 있습니다 (가정, 실측 필요).

### 1-2. PaddleOCR (PP-OCRv5, `lang="korean"`)

**무엇을 하는가**: 두 단계로 글자를 읽습니다.

1. **검출(det)**: 글자가 있는 영역을 4점 폴리곤으로 찾습니다. 기울어진 글자도 찾습니다.
2. **인식(rec)**: 각 영역의 글자를 문자열로 바꾸고 신뢰도를 매깁니다.

**시연 방법** (`OCR_example.py`): 간판·영수증·경고 표지판이 섞인 테스트 이미지를 직접 만들었습니다. 한글·영어·숫자를 섞고, 일부 글자는 8°·-5° 기울이고, 가우시안 블러를 주었습니다. 그 뒤 정답 텍스트와 문자 유사도를 비교했습니다.

**시연 결과** (`outputs/ocr_result.jpg`)

- 검출 영역 18개, 정답 10줄 중 **9줄 100% 일치**
- 유일한 불일치: `Physical AI Lab - OCR Demo` → 95.2%. 작은 하이픈(`-`)의 신뢰도가 낮게 나왔습니다.
- 기울어진 `출입금지`, `NO ENTRY`, `Tel. 02-1234-5678`도 모두 정확히 읽었습니다.
- 큰 글씨는 단어 단위로 쪼개져 검출됩니다 (`청년 / 피지컬AI / 일경험 / 프로젝트`). 그래서 평가 코드에서 연속된 결과를 이어 붙여 비교했습니다.
- 띄어쓰기는 일부 빠집니다 (`삼각김밥 1,500원` → `삼각김밥1,500원`). 평가에서는 공백을 지우고 비교했습니다.

### 1-3. SAM 2.1 (Segment Anything Model 2, Meta)

**무엇을 하는가**: SAM은 **"무엇"을 찾는 모델이 아닙니다.** **"어디"를 알려주면 그 물체의 정확한 윤곽(마스크)을 잘라내는** 모델입니다. 프롬프트가 위치 정보입니다.

| 모드 | 프롬프트 | 결과 파일 |
|---|---|---|
| Point | 물체 위의 점 하나 | `outputs/1_point.jpg` (왼쪽 사람) |
| Positive/Negative | 포함할 점(1) 2개 + 제외할 점(0) 1개 | `outputs/2_pos_neg_points.jpg` (버스에서 앞의 사람을 뺌) |
| Box | 박스 `[x1, y1, x2, y2]` | `outputs/3_box.jpg` (사람 2명) |
| Segment everything | 없음 | `outputs/4_everything.jpg` (전체 자동 분할) |

**특징**

- 경계 품질이 가장 좋습니다. 옷자락이나 팔 사이의 틈까지 정확하게 자릅니다.
- **클래스 이름이 나오지 않습니다.** 마스크만 나옵니다. "이게 사람인가?"는 다른 모델(YOLOE, SigLIP2)이 판단해야 합니다.
- 원래는 영상용 모델입니다. 첫 프레임에서 지정한 물체를 다음 프레임에서도 계속 추적할 수 있습니다. 이번 시연에서는 이미지 모드만 사용했습니다.
- Segment everything 모드는 이미지 전체에 점을 촘촘히 찍어 돌리기 때문에 느립니다.

### 1-4. SigLIP2 (Google, `google/siglip2-base-patch16-224`)

**무엇을 하는가**: 이미지 인코더와 텍스트 인코더가 짝을 이룹니다. 같은 뜻의 이미지와 문장이 **같은 벡터 공간의 가까운 위치**에 오도록 학습되었습니다. 탐지나 분할은 하지 않습니다. **이미지 전체(또는 잘라낸 영역) 하나에 벡터 하나**를 만듭니다.

**시연 방법** (`sigLIP2_example.py`): 이미지 3장(버스 crop, 보행자 crop, 축구 선수)과 문장 6개의 코사인 유사도 행렬을 계산했습니다. SigLIP 방식의 확률 `sigmoid(logit_scale × cos + logit_bias)`도 함께 출력했습니다.

**시연 결과** (`siglip2_similarity.jpg`)

| 이미지 | 정답 문장 유사도 | 2위 문장 유사도 | 판정 |
|---|---|---|---|
| Bus (crop) | **0.119** (a bus) | 0.061 (a person walking) | 정답 |
| Pedestrian (crop) | **0.090** (a person walking) | 0.056 (a bus) | 정답 |
| Soccer players | **0.086** (two soccer players) | 0.025 (a person walking) | 정답 |

- 3장 모두 정답 문장의 유사도가 가장 높았습니다.
- 코사인 값 자체는 0.1 안팎으로 작습니다. SigLIP 계열의 정상적인 특성입니다. **절대값이 아니라 상대 순위로 판단**해야 합니다.
- 버스 crop에 사람이 함께 찍혀 있어 `a person walking`도 0.061로 높게 나왔습니다. 이미지 하나에 벡터 하나라서, 여러 물체가 섞이면 의미도 섞입니다.

### 1-5. YOLOE (Ultralytics, `yoloe-26s-seg`)

**무엇을 하는가**: YOLO 계열의 실시간 탐지·분할 모델에 **열린 어휘(open-vocabulary)** 기능을 더했습니다. 학습하지 않은 클래스도 프롬프트로 찾을 수 있습니다. 텍스트 프롬프트는 MobileCLIP2 텍스트 인코더(`mobileclip2_b.ts`)로 벡터로 바꿉니다.

| 모드 | 프롬프트 | 시연 결과 |
|---|---|---|
| Text prompt | `"person wearing a white jacket"` | `1_text_prompt.jpg`: 흰 재킷을 입은 사람 **1명만** 탐지 (0.54). 검은 코트를 입은 사람은 제외 |
| Visual prompt (같은 이미지) | bus.jpg 속 사람 1명의 박스 | `2a_visual_prompt_same_image.jpg`: 같은 이미지에서 비슷한 객체 탐지 |
| Visual prompt (참조 이미지) | bus.jpg의 박스 → zidane.jpg에서 탐색 | `2b_visual_prompt_refer_image.jpg`: 다른 이미지에서 같은 종류 탐지 |
| Prompt free (`-pf`) | 없음 (내장 어휘 4,500+ 클래스) | `3_prompt_free.jpg`: bus 0.90, person 0.59~0.89, glasses 0.64, stop sign, traffic sign, boardwalk 등 |

**특징**

- **탐지 + 분할 + 클래스 이름**을 한 번에 출력합니다. 5개 모델 중 가장 "완성된" 결과입니다.
- 텍스트 프롬프트 모드에서는 `set_classes()`로 텍스트 임베딩을 미리 계산해 둡니다. 그래서 추론 속도는 일반 YOLO와 거의 같습니다.
- Prompt free 모드는 편하지만 오검출도 있습니다. 시연에서 보도를 `boardwalk`로, 버스 광고 그림을 `clip`으로 잡았습니다.

### 1-6. DINO-X (IDEA Research) — 공개 자료 기준, 미시연

**무엇을 하는가**: Grounding DINO 계열의 후속 모델입니다. Grounding DINO 1.5와 같은 Transformer 인코더-디코더 구조를 씁니다. "물체 단위"의 표현을 하나 만들고, 그 위에 여러 헤드를 붙여 **탐지·분할·키포인트·설명을 한 모델에서** 출력합니다.

**입력 (프롬프트)**

| 프롬프트 | 설명 | YOLOE 대응 모드 |
|---|---|---|
| Text prompt | 찾을 물체를 단어나 문장으로 지정 (예: `"person . chair . laptop"`) | Text prompt |
| Visual prompt | 예시 박스나 점으로 "이런 것"을 지정. 개수 세기(counting)에 특히 강함 | Visual prompt |
| Customized prompt | 특정 도메인용으로 미세조정한 프롬프트 벡터 | 없음 |
| Prompt-free | 범용 객체 프롬프트(universal object prompt)로 이미지 속 모든 물체를 찾고 이름을 붙임 | Prompt free |

**출력**

- 박스 + 클래스 (열린 어휘 탐지, phrase grounding)
- 분할 마스크
- 키포인트: 사람 자세, 손 자세
- 영역 설명(region captioning): 각 물체를 문장으로 설명
- 영역 기반 질의응답 (물체 단위)

**공개 성능** (DINO-X Pro, 제로샷 탐지)

| 벤치마크 | AP |
|---|---|
| COCO | 56.0 |
| LVIS-minival | 59.8 (희귀 클래스 63.3) |
| LVIS-val | 52.4 (희귀 클래스 56.5) |

- LVIS 희귀 클래스에서 이전 최고 성능보다 5.8 AP 높습니다. 학습 데이터에 거의 없는 **드문 물체**를 잘 찾는다는 뜻입니다.
- 학습에는 1억 개 이상의 grounding 샘플로 만든 **Grounding-100M** 데이터셋을 썼습니다.

**버전**

- **DINO-X Pro**: 성능 우선. 클라우드(DeepDataSpace) API로만 쓸 수 있습니다. API 토큰이 필요하고 호출량에 따라 비용이 듭니다.
- **DINO-X Edge**: 엣지 장비용 경량 버전입니다. 논문에서는 엣지 GPU에서 실시간에 가까운 속도를 보고합니다. 다만 공개 가중치로 바로 내려받아 쓰는 형태는 아닙니다 (사용 시점에 확인 필요).

**특징**

- YOLOE와 기능이 가장 많이 겹칩니다. 차이는 **정확도(특히 드문 물체)와 출력 종류**입니다. DINO-X는 키포인트와 영역 설명까지 줍니다.
- 반대로 **로컬 실행이 어렵습니다.** 이미지를 외부 서버로 보내야 하므로, 개인정보가 담긴 영상에는 쓰기 조심스럽습니다.
- `Grounded-SAM-2` 저장소에서 **DINO-X + SAM2** 조합(탐지 → 정밀 분할 → 영상 추적)을 공식 예제로 제공합니다.

## 2. 모델 비교

### 2-1. 기능 비교

| 비교 항목 | MediaPipe | OCR | SAM2 | SigLIP2 | YOLOE | DINO-X |
|---|---|---|---|---|---|---|
| 다루는 대상 | 사람(얼굴·손·몸)만 | 글자만 | 모든 물체 | 모든 이미지·문장 | 모든 물체 | 모든 물체 (드문 물체에 강함) |
| 위치 출력 | 키포인트 | 폴리곤 | 마스크 | 없음 | 박스 + 마스크 | 박스 + 마스크 + 키포인트 |
| 클래스·의미 출력 | 제스처 7종, 좌/우 손 | 글자 문자열 | **없음** | 문장과의 유사도 | 클래스 이름 | 클래스 이름 + 영역 설명 문장 |
| 텍스트 이해 | X | X (읽기만 함) | X | **O** | **O** (텍스트 프롬프트) | **O** |
| 프롬프트 | 없음 | 없음 | 점·박스 (필수에 가까움) | 텍스트 | 텍스트·박스·없음 | 텍스트·박스·맞춤·없음 |
| 새 클래스 추가 | 재학습 필요 | 해당 없음 | 해당 없음 | 문장만 바꾸면 됨 | 문장·박스만 바꾸면 됨 | 문장·박스만 바꾸면 됨 |
| 속도 (상대) | 매우 빠름 | 보통 | 느림 (everything 모드는 매우 느림) | 보통 | 빠름 | Pro는 네트워크 지연 포함, Edge는 빠름 |
| 엣지 배포 난이도 | 쉬움 (TFLite 기반) | 보통 | 어려움 (모델이 큼) | 어려움 (인코더가 큼) | 보통 (텍스트 고정 후 export) | 매우 어려움 (가중치 비공개, API 사용) |

### 2-2. 서로 어떻게 보완하는가

6개 모델은 경쟁 관계라기보다 **서로 빈 곳을 채우는 관계**입니다.

- **YOLOE → SAM2**: YOLOE가 박스와 클래스를 찾고, SAM2가 그 박스를 프롬프트로 받아 더 정확한 마스크를 만듭니다. SAM2에 없는 "무엇"을 YOLOE가 채웁니다.
- **YOLOE / SAM2 → SigLIP2**: 탐지·분할한 영역을 잘라 SigLIP2에 넣으면, 미리 정하지 않은 속성("의자에 앉은 사람", "노트북을 보는 사람")까지 문장으로 판별할 수 있습니다.
- **YOLOE → MediaPipe**: YOLOE로 사람 박스를 찾고, 그 영역에 MediaPipe Pose를 돌리면 자세(앉음·서 있음)를 알 수 있습니다.
- **YOLOE → OCR**: YOLOE로 표지판·화면·라벨 영역을 찾고, 그 안에서만 OCR을 돌리면 빠르고 오인식이 줄어듭니다.
- **DINO-X ↔ YOLOE**: 역할이 겹칩니다. 정확도가 중요한 오프라인 작업(라벨 생성, 정답 확인)에는 DINO-X를, 로컬에서 빠르게 반복하는 작업에는 YOLOE를 씁니다.
- **DINO-X → SAM2**: DINO-X의 박스를 SAM2에 넣어 마스크를 다듬고 영상에서 추적합니다 (Grounded-SAM-2 예제).

### 2-3. 고를 때의 기준

| 질문 | 고를 모델 |
|---|---|
| 사람의 자세·손동작·표정이 필요한가? | MediaPipe |
| 이미지 속 글자를 읽어야 하는가? | OCR |
| 물체의 정확한 경계(픽셀 단위)가 필요한가? | SAM2 |
| 이미지를 문장으로 검색·분류해야 하는가? 클래스를 미리 정할 수 없는가? | SigLIP2 |
| 무엇이 어디에 몇 개 있는지 실시간으로 알아야 하는가? | YOLOE |
| 드문 물체까지 가장 정확하게 찾아야 하고, 이미지를 외부 API로 보내도 되는가? | DINO-X |
| 탐지·분할·자세·설명을 한 번의 호출로 모두 받고 싶은가? | DINO-X |

## 3. 활용 분야 요약

### 3-1. 일반 활용

| 모델 | 활용 예 |
|---|---|
| **MediaPipe** | 운동 자세 코칭, 낙상 감지, 수어·제스처 인식, 비접촉 키오스크 조작, 운전자 졸음 감지(눈 깜빡임 블렌드쉐이프), AR 필터 |
| **OCR** | 영수증·명함·문서 디지털화, 번호판 인식, 계량기 검침, 물류 라벨·송장 읽기, 시각장애인용 글자 읽어주기 |
| **SAM2** | 데이터 라벨링 자동화(점 하나로 마스크 생성), 영상 편집(배경 제거·객체 추적), 의료 영상 분할, 로봇 파지 대상 영역 추출 |
| **SigLIP2** | 문장으로 사진 검색, 제로샷 이미지 분류, 중복·유사 이미지 찾기, 콘텐츠 필터링, 더 큰 VLM(예: PaliGemma)의 비전 인코더 |
| **YOLOE** | 학습 없이 새 물체 탐지 프로토타입, 안전모·조끼 착용 검사, 매장 상품 인식, 데이터셋 사전 라벨(pseudo-label) 생성 |
| **DINO-X** | 고품질 자동 라벨링, 밀집 물체 개수 세기(매장 진열대, 군중, 세포), 드문 물체 탐지(산업 결함, 희귀 부품), 로봇의 장면 이해(물체 + 설명), 작은 모델 학습용 정답 생성(지식 증류) |

### 3-2. OccuCool 프로젝트에서의 활용 (천장 카메라 인원 계수 → 냉방 제어)

`report/model_selection_report.md`에서 배포 모델은 **YOLO11n (head + person 2클래스)** 로 정했습니다. 오늘 시연한 모델 대부분은 i.MX 8M Plus NPU(2.3 TOPS)에 올리기에 크거나 무겁습니다. 그래서 **배포 모델이 아니라 개발 단계의 도구**로 쓰는 것이 현실적입니다.

| 모델 | OccuCool 활용 방안 | 단계 |
|---|---|---|
| **YOLOE** | 천장 시점 데이터에 `"head"`, `"person sitting at a desk"` 텍스트 프롬프트로 **자동 사전 라벨**을 만들고, 사람이 검수만 합니다. 라벨링 시간을 줄일 수 있습니다. | 데이터 준비 |
| **SAM2** | YOLOE나 사람이 찍은 박스를 SAM2로 다듬어 박스 품질을 맞춥니다. 영상 추적 기능으로 한 프레임만 라벨하고 나머지 프레임에 전파할 수 있습니다. | 데이터 준비 |
| **SigLIP2** | 수집한 영상을 문장으로 검색해 **어려운 샘플**("dark room with people", "crowded meeting room", "empty office")을 골라 학습·평가 세트의 분포를 맞춥니다. | 데이터 선별·평가 |
| **MediaPipe Pose** | 착석/서 있음 같은 자세 정보를 보조 라벨로 만들 수 있습니다. 단, 천장 시점에서는 정확도가 떨어질 수 있으므로 측면 카메라 데이터에만 쓰는 것이 안전합니다. | 보조 분석 (선택) |
| **DINO-X** | YOLOE보다 정확한 **사전 라벨 생성기·정답 확인용 기준 모델**로 씁니다. 특히 visual prompt counting으로 밀집한 회의실 장면의 인원 수를 따로 세어, YOLO11n 계수 결과와 비교하는 **교차 검증**에 쓸 수 있습니다. 단, 이미지가 외부 서버로 나가므로 **참가자 동의 범위에 클라우드 전송이 포함된 데이터만** 보냅니다. | 데이터 준비·평가 |
| **OCR** | 인원 계수와 직접 관계는 없습니다. 테스트 중 촬영 시각·장소 표지판을 자동으로 읽어 **데이터 메타정보를 기록**하거나, 에어컨 리모컨·온도계 화면의 숫자를 읽어 냉방 상태 로그로 쓸 수 있습니다. | 실험 기록 (선택) |

> 주의: PRD의 "영상 저장·외부 전송 0건" 요구는 **제품**에 대한 것입니다. 위 활용은 모두 동의를 받은 **별도 데이터 수집 세션**의 영상에만 적용합니다.

## 4. 결론

- **YOLOE**는 "무엇이 어디에"를 한 번에 주는 가장 실용적인 모델입니다. OccuCool에서는 **자동 라벨링 도구**로 가장 쓸모가 큽니다.
- **SAM2**는 경계 품질이 가장 좋지만 클래스를 모릅니다. **YOLOE와 짝으로** 써야 합니다.
- **SigLIP2**는 탐지를 하지 않는 대신 **문장으로 이미지를 검색·분류**할 수 있습니다. 데이터 선별에 유용합니다.
- **DINO-X**는 공개 성능이 가장 높고 출력 종류도 가장 많지만, 클라우드 API 전용입니다. OccuCool에서는 **정확도 기준선과 고품질 라벨 생성**에 쓰고, 개인정보 동의 범위를 꼭 확인해야 합니다.
- **MediaPipe**는 가볍고 빠르지만 사람의 몸 구조 전용이고 정면 시점에 맞춰져 있습니다.
- **OCR**은 한국어 성능이 시연에서 10줄 중 9줄 완전 일치로 좋았습니다. 다만 OccuCool의 핵심 기능과는 거리가 멉니다.
- 실제 엣지 배포 모델은 기존 계획대로 **YOLO11n**을 유지하고, 오늘의 모델들과 DINO-X는 **데이터 준비와 검증 품질을 높이는 도구**로 씁니다.
